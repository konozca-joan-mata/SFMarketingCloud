Automation & Journey Builder

Automatizando el ciclo de vida del cliente: desde trayectorias 1:1 en tiempo real con Journey Builder hasta procesos masivos de datos con Automation Studio.

⚡ Journey Builder: Orquestación 1:1

Journey Builder diseña trayectorias automatizadas que conectan datos, departamentos y canales para ofrecer experiencias individualizadas a cada cliente en el momento exacto.

¿Qué es una Trayectoria (Journey)?

  • Definición: Un flujo automatizado de comunicaciones e interacciones que guía a un contacto a través de una experiencia diseñada con tu marca.
  • 1:1 real: Cada contacto experimenta la trayectoria de forma individual, basada en sus propios datos y comportamientos en tiempo real.
  • Multicanal: Email, SMS, WhatsApp, push notification y actualizaciones en Sales Cloud, todo coordinado desde un único lienzo.
  • Orientado a objetivos: Cada journey tiene un Goal definido que determina el éxito (ej. "contacto realiza una compra").

Fuentes de Entrada (Entry Sources)

  • Data Extension Entry: Contactos de una DE de forma programada (ej. todos los días a las 9:00) o al cumplir criterios dinámicos.
  • API Event Entry: Un sistema externo envía un evento en tiempo real vía REST API para añadir contactos (ej. registro en web, compra completada).
  • Salesforce Data Entry: Cambios en objetos de Sales/Service Cloud disparan la entrada al journey (ej. cuando una Oportunidad se cierra como Ganada).
  • CloudPages Entry: Un contacto rellena un formulario en una landing page de Marketing Cloud.
  • WhatsApp / Inbound Chat: Un mensaje entrante del cliente inicia la trayectoria de conversación.

Actividades de una Trayectoria

  • Send Email: Envío de un email desde Content Builder. Configurable con remitente, asunto dinámico y audiencia.
  • Send SMS: Mensaje de texto vía MobileConnect.
  • Send WhatsApp: Mensaje de WhatsApp usando una plantilla aprobada por Meta.
  • Send Push Notification: Notificación push en la aplicación móvil del cliente.
  • Update Contact: Actualizar el valor de un atributo del contacto en MC (ej. marcar como "Onboardado").
  • Update CRM Record: Actualizar un campo en Salesforce CRM (ej. cambiar el Stage de un Lead).
  • Wait by Duration: Hacer esperar al contacto un tiempo definido (ej. 3 días) antes de la siguiente actividad.
  • Wait Until Date: Esperar hasta una fecha específica (ej. fecha de vencimiento del contrato del contacto).
  • Wait Until Event: Esperar hasta que ocurra un evento específico (apertura de email, clic) o que pase un tiempo máximo.

Control de Flujo: Splits y Joins

  • Decision Split: Divide el flujo según atributos del contacto o datos de una DE (ej. "¿es cliente VIP? Sí → camino A / No → camino B").
  • Engagement Split: Divide el flujo según si el contacto abrió o hizo clic en el último email enviado dentro de la trayectoria.
  • Random Split: Distribuye contactos aleatoriamente entre N caminos con porcentajes definidos. Ideal para pruebas A/B en journeys.
  • Einstein Split: Usa IA de Einstein para determinar el mejor camino para cada contacto según predicciones de comportamiento futuro.
  • Join: Reunifica múltiples caminos del flujo en un único punto antes de continuar con actividades comunes.

Configuración Avanzada: Goals, Exit y Re-entry

  • Journey Goal: Criterio de éxito de la trayectoria. Cuando un contacto lo cumple, puede salir antes de completar todos los pasos (ej. "ha realizado una compra").
  • Exit Criteria: Condición que fuerza la salida inmediata independientemente del punto en que esté el contacto (ej. "se ha dado de baja de comunicaciones").
  • Re-entry: Configura si un contacto puede volver a entrar a la trayectoria después de haberla completado, de haber cumplido el goal, o nunca.
  • Contact Evaluation: Define si los contactos del entry source se evalúan una sola vez o de forma continua (diariamente, cada hora, etc.).
  • Journey History: Registro de cada contacto que ha pasado por la trayectoria, con estado (activo, completado, salió por goal, error).

🎯 Campañas Clave con Journey Builder

Welcome Series (Serie de Bienvenida)

  • Objetivo: Incorporar a los nuevos suscriptores, presentar la marca y guiarlos hacia su primera acción de valor.
  • Entrada típica: API Event al registrarse en la web, o DE Entry cuando se añade a la lista de nuevos contactos.
  • Estructura recomendada:
    • Email 1 (inmediato): Bienvenida + confirmación y ventajas clave
    • Wait 2 días
    • Email 2: Presentación de productos o servicios estrella
    • Engagement Split: ¿Abrió Email 2?
    • Sí → Email 3: Oferta especial de bienvenida (más conversacional)
    • No → Email 3: Propuesta diferente con otro ángulo (más visual, más urgente)
  • Goal: "Contacto realizó su primera compra" o "Contacto completó su perfil".
  • Exit Criteria: Si el contacto se da de baja en cualquier punto, sale inmediatamente.

Behavioral Triggers: Abandono de Carrito

  • ¿Qué son? Trayectorias que se activan cuando un cliente realiza —o deja de realizar— una acción específica en tu plataforma digital.
  • Abandono de carrito: El cliente añade productos pero no completa la compra. MC detecta el evento vía API Event desde la plataforma ecommerce.
  • Flujo típico:
    • Trigger: API Event con los datos del carrito (productos, precios, imágenes)
    • Wait 1 hora → Email 1: "¿Olvidaste algo?" mostrando los productos del carrito
    • Decision Split: ¿Completó la compra? (consulta DE de compras)
    • No → Wait 24h → Email 2: Recordatorio con urgencia (stock limitado)
    • No → Wait 48h → Email 3: Descuento de recuperación exclusivo
    • Sí (en cualquier punto) → Exit automático vía Journey Goal
  • Datos necesarios: DE de carrito con ProductName, ProductImage, ProductURL, Price y ContactKey, consultables con AMPscript en el email.
  • Otros behavioral triggers: Browse abandonment (visitó una página de producto sin añadir al carrito), restablecimiento de contraseña expirado, renovación próxima.

Trayectorias por Etapa del Ciclo de Vida

  • Nurturing de Leads: Serie de emails educativos para leads que aún no están listos para comprar. Los mueve del awareness a la consideración con contenido de valor.
  • Onboarding de Cliente: Guía al nuevo cliente para que adopte el producto correctamente en los primeros 30-90 días. Reduce el churn temprano significativamente.
  • Cliente en Riesgo (Churn Prevention): Detecta señales de desenganche (sin compras en X días, sin aperturas de email) y activa intervención proactiva antes de la pérdida.
  • Re-engagement: Intenta recuperar suscriptores inactivos con propuesta de valor renovada. Si no reaccionan tras N intentos, se limpian de la lista activa.
  • Post-Purchase: Confirmación de pedido, instrucciones de uso, solicitud de reseña y propuesta de cross-sell en el momento de mayor satisfacción.
  • Renovación / Retención: Para suscripciones, inicia la secuencia 30/15/7 días antes del vencimiento con opciones de renovación y beneficios de fidelidad.

Journeys con Omnicanal: Coordinación de Canales

  • Principio: Un mismo journey puede orquestar email, SMS y WhatsApp según las preferencias y comportamientos del contacto.
  • Ejemplo: Email de confirmación de cita → si no abre en 24h → SMS recordatorio → si no confirma → WhatsApp con botón de confirmación.
  • Canal preferido: Usar un Decision Split para dirigir al contacto al canal que ha mostrado mayor engagement en el pasado.
  • Fatiga de canales: Configurar Journey Goal o Wait times para evitar saturar al contacto con mensajes repetidos en múltiples canales en pocos días.

⚙️ Automation Studio: Procesamiento en Lote

Automation Studio complementa a Journey Builder: mientras JB gestiona experiencias 1:1 en tiempo real, Automation Studio maneja procesos masivos de datos, importaciones y envíos programados.

¿Cuándo usar Automation Studio vs. Journey Builder?

  • Automation Studio: Procesos de datos recurrentes, importaciones de archivos, transformaciones SQL y envíos de email en lote sin necesidad de lógica 1:1.
  • Journey Builder: Comunicaciones personalizadas 1:1, trayectorias basadas en eventos de comportamiento en tiempo real o entradas individuales.
  • Uso combinado (patrón habitual): Automation Studio prepara y segmenta los datos nocturnamente → Journey Builder los consume al día siguiente para la comunicación personalizada.

Actividades de Automation Studio

  • SQL Query Activity: Escribe SQL para extraer, transformar y cargar datos entre Data Extensions. Potentísimo para segmentaciones complejas con múltiples tablas.
  • Import File Activity: Importa archivos desde el FTP/SFTP de MC hacia una Data Extension. Soporta CSV, TXT y otros formatos delimitados.
  • File Transfer Activity: Mueve o desencripta archivos dentro del sistema de archivos de MC (ej. de la carpeta de entrada a la carpeta de archivado).
  • Filter Activity: Aplica criterios de filtrado a una DE para generar una DE filtrada sin necesidad de SQL.
  • Data Extract Activity: Exporta datos de MC (métricas de envíos, registros de DE) al FTP en formato CSV para consumo externo por sistemas de BI.
  • Send Email Activity: Envío programado de un email a una DE o lista, equivalente a un envío desde Email Studio pero dentro de un flujo automático.
  • Script Activity: Ejecuta código SSJS para lógica avanzada de procesamiento de datos no posible con actividades estándar.
  • Wait Activity: Pausa la automatización por un período definido antes de continuar con la siguiente actividad.

Tipos de Programación y Disparadores

  • Scheduled Automation: Se ejecuta automáticamente según un horario recurrente (cada hora, diariamente a las 2:00 AM, los lunes, el primer día del mes, etc.).
  • File Drop Automation: Se activa cuando un archivo específico aterriza en el FTP de MC. Ideal para integraciones con sistemas externos que depositan datos regularmente.
  • Run Once: Ejecución manual única. Útil para cargas iniciales de datos, correcciones puntuales o pruebas de validación.

Casos de Uso Reales de Automation Studio

  • Segmentación nocturna: Query SQL a las 2:00 AM que extrae clientes activos de los últimos 30 días y los deposita en la DE de envíos del newsletter del día siguiente.
  • Importación diaria de leads: Sistema CRM externo deposita un CSV de leads en el FTP → File Drop activa la importación automática a una DE → Journey de nurturing arranca.
  • Limpieza semanal de datos: Query que elimina registros duplicados, contactos con bounces permanentes o datos con más de X meses de antigüedad sin actividad.
  • Export de métricas para BI: Data Extract nocturna que vuelca las métricas de campañas al FTP para que el sistema de Business Intelligence las consuma cada mañana.
  • Refresh de DE de audiencia: Query que recalcula diariamente qué contactos pertenecen a cada segmento (ej. "clientes VIP", "en riesgo") para usar en envíos o journeys.
